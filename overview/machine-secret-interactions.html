Machine Secrets & Hidden Interactions

This page is a source-traced sweep of every machine directory under ref/terf/function/entity/machines. "Secret" here means a non-obvious interaction, hidden mode, unusual coupling, or failure behavior that is easy to miss if you only look at recipes or block shapes.

57 machine directories reviewed Source-backed Not gameplay-validated

Method note: when a machine only exposed plain setup, tick, and operation behavior, this page says so directly instead of inventing extra secrets.

Shared Notes

  • Many multiblocks still inherit the same shared activation path: the Multiblock Core dispatch starts in startup.mcfunction and rotation matters before the machine-specific setup function even runs.
  • Several "machine interactions" actually live in tools. The Linker populates machine link arrays, the Crane Remote drives cranes by look direction, and capsules bring their own lock, unlock, and fluid payload behavior.
  • Panels and sensors are real operators in this codebase, not flavor blocks. Fission panels, OpenCore panels, STFR panels, and Warp Core panels all parse or present live machine state.
  • Mainframe-linked machines buffer their link id every tick, so a lot of "why did this stop working?" behavior is really networking state dropping rather than the machine forgetting its recipe.

A - F

  • Arc Furnace. It has a hidden block transmutation table in the block above the machine: TNT gets primed instead of quietly consumed, and an emerald block turns into custom palladium group metal.
  • Assembler. It doubles as a vehicle charger, needs a live mainframe link for normal operation, and its initialization field can crush entities caught inside the assembly volume.
  • Battery Array. The machine uses the cauldron underneath as an analog charge gauge and enters an overcharge path once stored power reaches max capacity.
  • Block Breaker. I did not find a hidden interaction surface beyond a 20-tick windup and the usual block break pulse.
  • Block Placer. It is really a six-direction observer-plus-dispenser adapter, so the "special" behavior is that the same machine logic supports all facings instead of one fixed front.
  • Breakers. It uses a button puzzle rather than a simple toggle: stone buttons keep it awake, a full polished blackstone button pattern turns it on, and red glazed terracotta under it blows the unit.
  • Capsule Interface. Right-click locks an inserted capsule, shift-right-click unlocks or ejects it, a lightning rod above hard-locks the whole interface, and an invalid antimatter setup can kill the machine core.
  • Charging Station. It only interacts with items carrying TERF's rechargable custom data, so it is tag-driven rather than item-type driven.
  • Chimney. I did not find a notable hidden interaction beyond its normal operation loop.
  • Chunk Loader. Respawn anchor charge count secretly sets the load radius: 1 charge loads only the local chunk, then 2, 3, and 4 charges expand to 3x3, 5x5, and 7x7 chunk squares.
  • Conveyor. A failed continuity check does not just stall it; the code destroys the multiblock core and then recursively explodes the belt line.
  • Crane. The machine is remote-operated: move, lower, raise, and detach behavior is driven by the Crane Remote and the player's look direction rather than by clicking the crane itself.
  • Crusher. I did not find a hidden interaction surface beyond normal case validation, stored-recipe matching, and power-gated processing.
  • Deuterium Concentrator. I did not find a non-obvious player interaction beyond ordinary checks, structure validation, and operation flow.
  • Dev Block. This is a true debug machine: if the backing command block text is literally infinite power, it flips into generator mode and becomes an absurd free power source.
  • Diesel Generator. It only spins up in non-space dimensions and only while the decorative copper case is intact, so the case is functional rather than cosmetic.
  • EBF. I only found a custom item-display helper alongside normal process files; no separate hidden interaction surface stood out.
  • Electric Press. I did not find a notable hidden interaction beyond normal recipe processing.
  • Electrolyzer. Activation is effectively recipe programming: it removes a measured amount of fluid, stores the matched recipe, and then runs from that stored state.
  • Extrusion Press. It secretly behaves like a mold-wear machine too, because activation decrements the input item and then removes durability from the mold slot.
  • Fabricator. It has two distinct trigger modes at the control block in front of it: a powered=true source such as a lever behaves like a normal craft trigger, but a lit=true source such as a redstone torch switches the machine into automation mode. In automation mode the recipe check aborts if any occupied slot is down to a single item, which means one copy of each ingredient can intentionally stay behind as a permanent recipe template.
  • Fission Fuel Loader. This is not a generic inserter; it has dedicated fuel-add, fuel-check, reset, and particle-on-top behavior for loading the fission system.
  • Fission Reactor. Fuel rods locally spread heat and decay, self-cool through air or water, emit steam when hot enough, and spawn new neutrons unless a neutron is already overlapping the rod.
  • Fission Reactor Panel. Its screens distinguish "No Sensor" from "No Rod Data," and it alarms when linked rod temperature crosses the 600 C threshold.
  • Fission Sensor. This is a scan head, not a processor: it only becomes interesting when linked, then it aggregates nearby rod temperature and neutron speed into panel-friendly readouts.
  • Fluid Pump. On first use it self-initializes a built-in water tank and then only pumps source water while the stored amount is below a threshold.
  • Fluid Tank. Its capacity shape is not fixed to one prefab; the floodfill and transform helpers show that connected iron-trapdoor geometry is used to decide what counts as the tank.

G - M

  • Gear Elevator. Floor calling and door control are link-driven: linked buttons select heights, linked levers mirror arrival state, and starting the elevator automatically closes doors.
  • Hadron Collider. Activation consumes two side inputs, scales max power storage to measured ring length, and has a beam-loop special case that notices when the ring path reaches its own current marker.
  • Lamp Controller. It iterates a buffered list of linked lamps and levers, so it is more like a scripted lighting bus than a single lamp switch.
  • Large Fluid Solidifier. Its outputs are partly randomized: the random helpers can turn one branch into powder snow instead of ice and roll ores from iron all the way up to rare ancient debris.
  • Laser. Beam color is tinted by stained glass, observers can redirect the beam based on facing, and side acacia signs act as power-setting screens.
  • Magma Drill. I did not find a hidden player-facing interaction beyond its normal drilling loop.
  • Mainframe. This is a true GUI network machine: it links and unlinks machine ids, tracks input and output machine lists, and can enter a rebooting crash path when load exceeds connected servers.
  • MCFR. The most non-obvious part is not a button or panel but its failure chain: leak, vent, overpressure, and detonation branches sit alongside the main reactor math.
  • Multi Piston. I did not find a hidden UI; its special behavior is purely mechanical, with separate push and retract phases for rods and frames.

N - S

  • OpenCore. It has a hidden startup soundtrack split, with a rare remix branch, and the indexing phase also drags in up to three nearby item entities per tick while looking for a valid recipe item.
  • OpenCore Control Panel. This is a real operator console with screen-click states for startup, laser displays, and stats, not just a read-only decoration block.
  • Ore Drill. Drill bit material is encoded by the wall block above the head, which secretly changes fortune, durability, and break speed before the bit eventually snaps.
  • Pressurizer. It refuses to run in space, pressurizes by summoning and storing gas stand entities, and depressurization purges the store with a very loud multi-sound vent event.
  • Purifier. I did not find a notable hidden interaction beyond ordinary operation.
  • Redstone Probe. It is only really useful as a linked machine sensor; the machine-local logic just forwards machine state into attached indicator bulbs or redstone-facing readouts.
  • Rolling Mill. It follows the same manual activation and stored-recipe pattern as other press-line machines, but I did not find an extra hidden side mode beyond that.
  • Security Terminal. The sign screen is clickable, it manages whitelists and linked machine ids, and it can toggle every linked machine sharing the same mainframe connection.
  • Security Turret. It is a mainframe-aware defense node that raycasts for targets, distinguishes player and entity hit paths, and carries its own explosion fallback.
  • Shearing Press. It has a manual activation path and custom argument helper, but I did not find a deeper hidden interaction than that.
  • Solar Panel. Network recalculation is triggered globally through the player lapis-break and lapis-place path, and crossed wiring can mark the machine as kaput and explode it.
  • Stasis Laser. A stone-button start can kick off an STFR-linked event sequence with end-crystal visuals, camera shake, music swaps, and reactor-side effects instead of a simple beam fire.
  • Steam Engine. I did not find a hidden player-facing mode beyond water loading, running, and failure explosion handling.
  • STFR. This is the largest hidden-interaction machine in the pack: maintenance mode, capsule receptacles, case shielding, startup overloads, radiation and power surges, sculk breakout, shutdown failure, and self-destruct all live here.
  • STFR Control Panel. It exposes plus-one and minus-one setpoint buttons, live graphs, alarm mute behavior, and dedicated self-destruct and startup-overload screens.

T - W

  • Turbine Large. The machine hides its danger in shaft and wire checks: structure failure routes into an explosion raycast rather than a quiet shutdown.
  • Turbine Medium. Its special behavior is drum-sensitive failure, including dedicated drum checks and drum explosion handling.
  • Variable Resistor. This oddball tags itself as both a power generator and a power consumer, so it behaves more like a controllable power-routing component than a normal single-role machine.
  • Warp Core. Warps are screen-programmed, coordinate-validated, and dimension-validated before firing; if validation or transit goes wrong, a warp-fail branch turns the field into a fire-filled disaster zone.
  • Warp Core Panel. The panel parses negative ship size, positive ship size, target coordinates, and target dimension from separate screens, and it backfills default coordinates from the current location when the panel values are invalid.
  • Wet Mill. I did not find a hidden interaction beyond normal item check, process, and completion flow.
